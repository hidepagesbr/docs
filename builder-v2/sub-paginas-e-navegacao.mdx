Uma página do Builder pode ter várias **sub-páginas**: uma pré-venda, a oferta, uma página de saída. O visitante passa de uma para outra **sem trocar de URL**, o que mantém o funil inteiro na mesma estrutura.

## O painel Páginas

<Print src="builder/painel-paginas" alt="Painel Páginas com as sub-páginas Pré-venda e Oferta e as ferramentas" />

- A lista mostra as sub-páginas. Os selos indicam o papel de cada uma: **Principal**, **Inicial**, **Pré-venda**, **Upsell**, **Downsell** e **Backredirect**.
- **Adicionar página** cria uma nova sub-página.
- A **Inicial** é a primeira que o visitante vê.

O menu **⋯** de cada sub-página tem:

| Opção | O que faz |
|---|---|
| **Renomear** | Troca o nome. |
| **Duplicar** | Cria uma cópia da sub-página. |
| **Clonar nesta página** | Substitui o conteúdo pelo de um site ou de outra página sua. |
| **Copiar ID da página** | Copia o ID, usado na navegação por código. |
| **Definir como página inicial** | Faz dela a primeira página. |
| **Excluir** | Remove a sub-página. |

Em **Ferramentas**, **Análise de etapas** mostra quantos visitantes passam de uma sub-página para a próxima, por campanha.

<Tip>
Um funil comum: na **pré-venda**, o botão leva para a sub-página **Oferta**. Na oferta, o botão de compra usa **URL externa** com o link do checkout.
</Tip>

<Info>
**Trocar links em massa**, em **Página atual**, troca de uma vez todos os links que apontam para um destino, por exemplo o link antigo do checkout pelo novo.
</Info>

## Backredirect

O **backredirect** mostra uma sub-página quando o visitante tenta sair: botão de voltar do navegador e, com **Intenção de saída** ligada, o cursor indo para fechar a aba.

<Print src="builder/backredirect" alt="Seção Backredirect em Página atual, com o destino e a opção Intenção de saída" />

Configure em **Página atual → Backredirect**: escolha a sub-página de destino e ligue ou desligue a **Intenção de saída**.

## Navegação por código

Num widget **HTML**, você navega entre sub-páginas pelo ID:

```html
<a data-page-link="ID_DA_PAGINA">Continuar</a>
```

```js
pageNavigator.goTo("ID_DA_PAGINA");
```

O ID está em **Página atual → ID da página** ou em **Copiar ID da página**, no menu da sub-página.

## Análise de etapas

A **Análise de etapas** mostra quantos visitantes chegaram em cada sub-página e quantos passaram de uma para a outra. Abra pelo painel **Páginas** do editor, em **Ferramentas → Análise de etapas**, ou pela lista de páginas, no menu **⋮** do card → **Analytics**.

- Cada barra é uma sub-página, com o nome dela, **na ordem do funil**: a primeira página, depois as páginas para onde os links levam, na ordem em que aparecem.
- Páginas que nenhum link alcança, como política de privacidade e backredirect, aparecem no fim e ficam fora da **Taxa entre etapas**.
- Escolha o período e, se a página estiver em mais de uma campanha, uma campanha ou **Todas as campanhas**.
- Uma sub-página apagada depois de receber visitas aparece como **Página removida**.

<Note>
A análise usa a versão **publicada** da página. Se você reordenar o funil, a ordem nova aparece depois de publicar.
</Note>

<Tip>
Uma etapa com mais visitas que a anterior indica tráfego entrando direto nela, sem passar pela etapa de cima, como um anúncio apontando para uma sub-página no meio do funil.
</Tip>

Os mesmos números estão na API, em [`GET /v1/analytics/funnel-steps`](/api/guias/analytics#etapas-do-funil).
