O RedTrack credita a venda pelo **click-id**: ele precisa chegar até o checkout, e o **postback do gateway** para o RedTrack devolve a venda. O que muda é **quem leva o click-id até o checkout**, e isso depende do modo da Black Page na campanha.

| Modo da Black | Quem leva o click-id ao checkout | Venda no painel do HidePages |
|---------------|----------------------------------|:---:|
| **Nativo** (página do Builder) | Os scripts que você cola na página | ✅ com uma integração de conversão |
| **Mirror** | O HidePages, automaticamente | — |
| **Redirect** | A sua página de destino | — |

<Info>
O RedTrack não é uma integração no painel do HidePages: não existe campo de domínio nem de postback do RedTrack. O postback que credita a venda sai **do gateway** e é configurado no gateway e no RedTrack.
</Info>

## Nativo

A oferta é uma página do Builder. O link do RedTrack aponta para a URL da campanha no HidePages, com o `hpid` e os parâmetros da sua fonte de tráfego.

<Steps>
  <Step title="Pegue o script do RedTrack">
    O `track.js` da campanha no RedTrack, com o seu domínio de tracking e o `rtkcmpid`.
  </Step>
  <Step title="Cole os dois scripts no Head da Black Page">
    No Builder, abra **Scripts → Head** e cole o `track.js` e, depois dele, o encaminhador do `clickid` (abaixo). Veja [Página e scripts](/builder-v2/pagina-e-scripts).
  </Step>
  <Step title="Publique a página" />
  <Step title="Configure o postback do gateway para o RedTrack">
    No gateway, o postback server-to-server do RedTrack, repassando o `clickid`.
  </Step>
</Steps>

**1. Script de rastreamento do RedTrack**

```html
<script type="text/javascript" src="https://trk.seudominio.com/track.js?rtkcmpid=xxxxxxxxxxxxx"></script>
```

**2. Encaminhador do `clickid` para o checkout**

```html
<script>
(function () {
  var PARAM = "clickid";

  function gc(name) {
    var parts = document.cookie.split(/;\s*/);
    for (var i = 0; i < parts.length; i++) {
      var eq = parts[i].indexOf("=");
      if (eq === -1) continue;
      if (parts[i].substring(0, eq).trim() === name)
        return parts[i].substring(eq + 1);
    }
    return "";
  }

  function getId() {
    var raw = gc("rtkclickid-store");
    if (!raw) return "";
    var dec = raw;
    try { dec = decodeURIComponent(raw); } catch (e) {}
    try {
      var j = JSON.parse(dec);
      if (j && typeof j === "object") return j.rtkcid || j.clickid || "";
    } catch (e) {}
    return dec.trim();
  }

  function fix(a, val) {
    try {
      var u = new URL(a.href);
      if (u.origin === location.origin) return;
      u.searchParams.set(PARAM, val);
      a.href = u.toString();
    } catch (e) {}
  }

  function run() {
    var val = getId();
    if (!val) return;
    document.querySelectorAll("a[href]").forEach(function (a) { fix(a, val); });
  }

  function boot() {
    run();
    [500, 1500, 3000, 6000, 10000].forEach(function (ms) { setTimeout(run, ms); });
  }
  if (document.readyState === "loading") document.addEventListener("DOMContentLoaded", boot);
  else setTimeout(boot, 0);

  document.addEventListener("click", function (e) {
    var val = getId();
    if (!val) return;
    var path = e.composedPath ? e.composedPath() : [];
    for (var i = 0; i < path.length; i++) {
      if (path[i].tagName === "A" && path[i].href) { fix(path[i], val); return; }
    }
  }, true);
})();
</script>
```
<Warning>
Troque `trk.seudominio.com` e `rtkcmpid=xxxxxxxxxxxxx` pelos valores da sua conta RedTrack. `PARAM = "clickid"` é o parâmetro que leva o click-id ao checkout: ele precisa ser o mesmo que o gateway devolve ao RedTrack no postback.
</Warning>

O `track.js` grava o click-id no cookie `rtkclickid-store`. O encaminhador lê esse cookie e acrescenta o `clickid` em todos os links **externos** da página. Ele repete a operação por alguns segundos e também no clique, o que cobre botões de pacote e players de VSL que trocam o link na hora.

### Parâmetro RedTrack na integração

Para ver as vendas **também no painel do HidePages**, crie uma [integração de conversão](/conversoes/integrar-gateway). Se o seu RedTrack já repassa um `sub` para o gateway pela Offer URL, selecione esse `sub` (de `sub1` a `sub20`) como **Parâmetro RedTrack** no mesmo campo do parâmetro do gateway.

<Print src="conversoes/parametro-popover" alt="Seletor de parâmetros da Hotmart com sck e a lista de parâmetros RedTrack" />

O painel mostra então a configuração que o RedTrack precisa:

<Print src="conversoes/redtrack-guia" alt="Guia Configuração do RedTrack com os passos para Traffic Channel e Offer URL" />

1. No **Traffic Channel** do RedTrack, `sub1` entra como parâmetro de rastreamento na URL da campanha.
2. Na **Offer URL** do RedTrack, o valor de `sub1` vai para um parâmetro aceito pelo gateway, por exemplo `?sck={sub1}`.
3. O parâmetro da Offer URL não pode estar em uso na fonte de tráfego.

<Warning>
A chave do HidePages vai só no parâmetro do gateway (no exemplo, `sck`). Use parâmetros **diferentes** para a chave do HidePages e para o `clickid` do RedTrack, para um não sobrescrever o outro no checkout.
</Warning>

## Mirror

Em **Mirror**, o HidePages serve a sua página de oferta hospedada fora, sob o domínio da campanha. Os scripts do RedTrack são os que já estão **na sua página de origem**: não cole nada no HidePages.

O visitante chega pelo **link de clique do RedTrack**, que redireciona para a URL da campanha com o click-id na query. O HidePages lê esse click-id e o acrescenta como `clickid` nos links de checkout da página espelhada, inclusive nos links que o script da página monta depois de carregar.

<Steps>
  <Step title="Na campanha, Black Page em Mirror">
    Informe a URL da sua página de oferta. Veja [os três modos](/conceitos/modos-de-entrega).
  </Step>
  <Step title="No RedTrack, a Offer URL é a URL da campanha">
    Com o `hpid` e os parâmetros que você usa.
  </Step>
  <Step title="Postback do gateway para o RedTrack">
    Igual ao Nativo.
  </Step>
</Steps>

<Note>
No Mirror, a chave `hp1_` do HidePages não é acrescentada. As vendas aparecem no RedTrack, não no painel de conversões do HidePages.
</Note>

## Redirect

Em **Redirect**, o visitante aprovado é enviado para a URL da Black Page. O HidePages **repassa a query** do visitante: UTMs, `sub1`…`sub10`, click-ids. Só o `hpid` é retirado.

Todo o rastreamento fica **na página de destino**: o `track.js` do RedTrack e o encaminhamento do click-id ao checkout são configurados lá, como você faria sem o HidePages.

## Pixels

Pixels de Facebook, Google e outros vão no mesmo lugar dos scripts: **Scripts** da página no Nativo, ou na própria página nos modos Mirror e Redirect.
